# Template and segment authoring

This M0 guide defines how to author reusable templates and release-specific
segments for the ChimpMaera video reference. It is documentation only: it does
not implement selection, rendering, assembly, upload, or publication.

## Authoring model

- A **template** is a reusable, versioned JSON contract under `../templates/`.
- A **segment** is release-specific editorial input in a Daily POC manifest's
  `video.segments` array. It binds stable claims and evidence without changing
  their maturity.
- Generated narration, storyboards, and adapters are evidence. Never edit them
  directly; change the canonical manifest or the reusable template instead.

Start from the current public examples, copy the selected template into a new
versioned file, and assign a new stable ID and explicit version. Do not
overwrite a previously consumed template version.

For a release segment, edit only the canonical manifest and keep one stable
segment ID, unique order, logical duration, purpose, narration, visuals, claim
references, and use-case references:

```json
{
  "id": "SEG-RELEASE-SUMMARY",
  "order": 10,
  "purpose": "Explain one verified user-visible increment",
  "narration": "The candidate now rejects an unbound release claim.",
  "visuals": ["Show the failing gate and its evidence identifier."],
  "claimRefs": ["CM-CLAIM-EXAMPLE"],
  "useCaseRefs": ["USE-CASE-EXAMPLE"]
}
```

The repository schema and example manifest remain authoritative for exact
fields. The example above illustrates intent and is not a replacement schema.

## Versioning and supersession

Use immutable filenames ending in `-vN.json` for meaning-changing template
revisions. Compatible editorial corrections may retain a version only before
that revision has been consumed. Once consumed, add the successor, record why
it supersedes the prior revision, and keep the prior bytes available for
provenance. A successor never silently widens claims, rights, public actions,
or evidence maturity.

Release segments are versioned through the Daily candidate identity
`v<next-semver>-poc.YYYYMMDD.N`. Increment `N` when editorial candidate identity
changes on the same day. Preserve blocked candidate reports and prior snapshots
as negative evidence; do not rewrite history.

## Local checks

From the repository root, validate the reference and the Daily contract before
considering an authored change acceptable:

```bash
python3 tools/video-production-reference/scripts/verify_reference_closure.py
npm run video:test
npm run daily-poc:test
```

For an actual clean, frozen source and canonical manifest, prepare and verify
into a new owned output directory:

```bash
node scripts/daily-poc.mjs prepare \
  --manifest /path/to/manifest.json \
  --source-repo /path/to/clean/frozen/source \
  --output /path/to/new/candidate-output
node scripts/daily-poc.mjs verify \
  --manifest /path/to/manifest.json \
  --source-repo /path/to/clean/frozen/source \
  --output /path/to/new/candidate-output
(cd /path/to/new/candidate-output && sha256sum -c SHA256SUMS)
```

## Acceptance checklist

- Template and segment IDs are stable, unique, and bound to explicit versions.
- Claims, non-claims, use cases, evidence, assets, and digests resolve exactly.
- Scene order is deterministic; no wall-clock value or nondeterministic choice
  affects generated bytes.
- Render and all public actions remain disabled unless their separate existing
  gates and exact approvals are satisfied.
- Reference closure, focused video tests, Daily tests, deterministic verify,
  and checksums pass without weakening a gate.
- Human editorial and visual review still applies to the exact candidate
  revision; a local pass is not a release or publication claim.

## Rollback

If validation or review fails, preserve the blocked report, stop the candidate,
and revert only the unaccepted template/manifest revision. Restore the last
accepted immutable template reference and prepare into a new output directory.
Never repair generated bytes, reuse a drifted output directory, lower evidence
maturity, or enable publication to make a check pass.
