# ChimpMaera v0.2 Wave 3 — minimal Paperless-ngx zoo adapter PDCA

Date: 2026-07-31  
Scope: read-only adapter slice, synthetic metadata only  
Maturity verdict: **HIGH for a disabled-by-default read-only HTTP adapter; LOW for ingest/lifecycle or bundled service**

## PLAN

The repository has no Paperless service, artifact pin, database/queue/converter
lock, backup/restore evidence or hostile-document isolation. Adding Paperless
to Compose would therefore be an unsupported supply-chain and lifecycle claim.
The smallest honest Wave 3 slice is a real HTTP adapter contract that can read
only bounded synthetic zoo metadata from an explicitly configured Paperless-
ngx API. It is disabled in the stock demo and does not make installation or
compatibility claims.

Allowed operations are fixed list and numeric-ID metadata read. The base URL is
constructor-owned, credentials are injected, request paths are constructed by
the adapter, and returned records are sanitized. Upload, content download,
preview, OCR, URL ingest, mail, mutation, delete, bulk, retention and arbitrary
query/path operations are absent. Only titles with the fixed synthetic zoo
prefix cross the adapter boundary. Receipts expose digests and counts, never
tokens or raw document content.

## Adversarial review and gates

| Failure | Control | Evidence |
|---|---|---|
| SSRF/path injection | fixed base/path; numeric IDs; no caller URL/path | invalid input denied, zero fetch |
| Token disclosure | Authorization created internally; output/error redacted | output/error tests |
| Non-zoo data leakage | fixed query plus local prefix filter | mixed response filter test |
| Oversized/unbounded result | fixed page size and maximum accepted results | oversized response deny |
| Provider schema drift | strict envelope/material field validation | malformed response matrix |
| Mutation by adapter | only GET accepted by internal call | fetch call assertions |
| False runtime claim | stock mode remains `off`; docs name unproven integration | static config/docs tests |

White tests use a fake HTTP boundary to prove exact Paperless API requests,
sanitized metadata and digest receipt. Black tests cover invalid token/base/ID,
redirect-like values, malformed/oversized/mixed data and provider errors.
