## Rollback choices

Use suffix rollback boundaries: later dependent waves are removed before an
earlier wave. Each sequence below was applied with `git revert --no-commit` in
an isolated clone and passed the resulting repository test suite.

| Intended boundary | Revert in this order | Result |
|---|---|---|
| Remove W4 supply-chain plus stability | `f12dbea f0c0b3a 1b9e6bc` | 66/66 |
| Remove W3 and later | previous sequence, then `a32623c` | 62/62 |
| Remove W2 and later | previous sequence, then `2f89e07` | 59/59 |
| Remove all v0.2 | previous sequence, then `dcc1050 6154a50` | 50/50; exact `v0.1.0` baseline tree |

Reverting only `f12dbea` is mechanically clean and passes the older 68-test
suite, but it reopens the proven symlink/path-escape defect. It is therefore
an emergency diagnostic boundary, not an acceptable normal rollback.

Before any owner-authorized rollback, create a backup branch, use a fresh
clone, inspect the staged revert, and rerun the checks appropriate to the
resulting boundary. If a partial rollback conflicts, fall back to the next
larger validated suffix boundary; the conservative final fallback is the
exact `v0.1.0` tree.
