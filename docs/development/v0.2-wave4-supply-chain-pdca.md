# ChimpMaera v0.2 Wave 4 — supply-chain hardening PDCA

Date: 2026-07-31  
Scope: repository-local artifact lock and deterministic verification  
Maturity verdict: **HIGH for declared-input verification; LOW for external provenance/vulnerability guarantees**

## PLAN

Current strengths are digest-pinned runtime/Compose OCI references, npm lock
integrity and commit-pinned CI actions. Gaps are that those declarations are
not unified or mechanically compared, new runtime files can be omitted from
the Docker build/release, development evidence is not explicitly separated
from the public file closure, and no deterministic supply-chain report exists.

Wave 4 adds a versioned artifact lock and a local verifier that checks exact OCI
references across Compose and Dockerfiles, npm lock integrity presence, full
SHA CI actions, runtime COPY closure, release manifest closure and selected
security settings. Its JSON output is evidence about repository declarations,
not an SBOM, signature, provenance, CVE or license-clearance claim.

## Adversarial review and gates

White tests: current pinned OCI inputs, npm lock, CI action pins, runtime module
copy closure and release manifest pass. Black fixtures: mutable tag, digest
drift, missing npm integrity, short action ref, omitted runtime module and
unmanifested public source each fail.

The verifier must be offline, deterministic, side-effect free and return a
non-zero status on mismatch. The lock must distinguish `DECLARATION_PINNED`
from `SIGNATURE_NOT_VERIFIED` and record Paperless as deliberately absent.

## ACT / autonomous decision audit

- Assumption: declaration verification is valuable without network trust
  services. Risk: it can be overread as provenance. Fallback: machine-readable
  claim limits and explicit docs.
- Assumption: no new Paperless OCI image belongs in the lock because Wave 3
  installs none. Risk: adapter users need their own artifact policy. Fallback:
  gate future stock enablement on adding the complete Paperless stack lock.
- Claim limit: no registry signature, SLSA provenance, vulnerability scan,
  transitive container SBOM, license audit or rebuild reproducibility is proven.
