# ChimpMaera v0.2 Approval Workbench — PDCA-reviewed implementation plan

Date: 2026-07-31  
Scope: local deterministic PoC, feature branch only  
Plan maturity verdict: **HIGH for Wave 1; later waves explicitly gated**

## PLAN — observed baseline and independent scouts

Three independent read-only scouts examined the current effect gate/Admin-AI,
the provider-neutral policy seam, and Paperless/supply-chain implications. No
scout edited files or installed software.

### Current approval/effect boundary

- Startup pins the authority, catalog and static Admin-AI policy manifests by
  digest; local POSTs require bearer auth, exact Origin/Host and CSRF.
- The deterministic policy has exactly one `AUTO_GRANT`, one
  `OWNER_ESCALATION`, and a wildcard `DENY`. Only `AUTO_GRANT` receives
  authority; escalation is display-only.
- The effect gate binds exact action/scope/replay/policy data and reads the
  provider back, but the Admin-AI action allowlist currently contains only the
  contact action.
- Existing sequential replay is idempotent. It does not prevent two concurrent
  first calls, a crash between provider acceptance and persistence, or semantic
  mismatch hidden inside a merely non-null readback.
- There is no owner-decision receipt, durable pending proposal, expiring lease,
  lease consumption state, or owner-decision endpoint.

Primary evidence: `demo/runtime/admin-ai-poc.mjs`,
`demo/runtime/enforcement-gate.mjs`, `demo/runtime/server.mjs`,
`packages/setup-coordinator/src/index.ts`, and their existing tests.

### Provider-neutral contract seam

The safe eventual seam is:

`neutral intent → effect-free adapter plan → PolicyEvaluator → validated decision → gate-issued authority → provider adapter → readback receipt`.

The evaluator must return a decision, never authority. Trusted policy/profile
context must be server-owned. A future versioned contract should bind actor,
capability, materiality, adapter/version, action/scope digests, replay key,
policy generation and decision constraints. The current runtime mixes
provider-specific action construction with policy evaluation and uses different
digest encodings across TypeScript and demo contracts.

**Wave 1 choice:** document the interface but defer code. Introducing a new
cross-package contract, legacy adapter, registry and digest migration while
changing approval enforcement would destabilize the security-critical Wave 1
boundary.

### Paperless and supply chain

Paperless is absent and DMS is explicitly `off`. The current document catalog
entry is synthetic while the v1 setup contract rejects containers, credentials,
network endpoints and downloads. A real Paperless entry would therefore make a
false compatibility claim.

Current positives include digest-pinned OCI images, npm integrity locks,
commit-pinned CI actions and deterministic release checksums. Gaps relevant to
any later Paperless wave include absent SBOM/provenance/signatures, mutable CI
runner naming, npm-version drift, no vulnerability/license evidence, no offline
bundle, and incomplete running-image readback.

**Wave 1 choice:** no Paperless/runtime/supply-chain implementation. Later work
requires a versioned real-service setup contract and artifact lock before any
smoke.

## Wave separation

### Current implementation wave — Wave 1

Additive local Approval Workbench for the existing synthetic Dolibarr order:

1. Policy response contains an exact, readable business diff and a digest that
   is part of the deterministic decision digest.
2. A durable workbench registers only server-produced
   `OWNER_ESCALATION` proposals.
3. Authenticated owner endpoint accepts exactly `APPROVE` or `REJECT` for an
   exact decision digest. It emits a digest-bound owner-decision receipt.
4. Approval causes the trusted gate to issue a SAFE_GUIDED-bound, policy-bound,
   exact-scope/action/diff, short-lived, one-use HMAC lease. Rejection has no
   authority.
5. The effect gate validates the entire lease at use time, reserves the lease
   and replay key durably before provider access, performs the exact synthetic
   mutation, semantically checks readback, and emits an effect receipt bound to
   the owner-decision receipt and lease.
6. Approval and effect receipt readback endpoints expose stored evidence.
7. Dashboard renders the business diff and real Approve/Reject controls while
   retaining the explicit “deterministic, no live LLM” statement.

Existing contact `AUTO_GRANT` and installer demo behavior remain compatible.

### Later Wave 2 — provider-neutral policy contract

Implementation-ready contract (deferred):

- `PolicyEvaluationInputV1`: actor, neutral capability/operation/resource/
  tenant/materiality, adapter ID/version, exact action/scope digests, replay key.
- `TrustedPolicyContextV1`: server-owned profile ID/generation and policy
  ID/generation/digest/evaluation time.
- `PolicyDecisionV1`: outcome/reasons, exact input/effect binding, constraints,
  and canonical decision digest.
- `PolicyEvaluatorV1.evaluate(input, trustedContext)` returns data only.
- Gate revalidates the complete decision; a closed adapter registry maps a
  neutral capability to a typed provider action. Unknown/malformed/timeout
  results deny with no auto-grant fallback.
- Migrate additively behind the existing v1 endpoint; standardize digest
  encoding and distinguish source-byte from semantic policy digests.

Gate to start: Wave 1 isolated and green; contract/schema review complete;
legacy response parity tests; failure/timeout/cancellation limits specified.

### Later Wave 3 — Paperless-ngx

- Wave 3A read-only synthetic pilot on private networks with least-privilege API
  identity, digest/redacted receipts, and hostile-document handling.
- Wave 3B bounded ingest/classification with exact bytes/MIME/size/metadata/
  instance binding and asynchronous `PLANNED → APPROVED → SUBMITTED →
  COMPLETED | FAILED | AMBIGUOUS` reconciliation.
- Wave 3C lifecycle/delete/bulk/retention/email/URL actions only after verified
  backup, restore, legal-hold and compensating-operation tests.

Gate to start: real-service setup contract; pinned artifact lock for Paperless,
database, queue and converters; SBOM/provenance/signature policy; CVE/license
gates; default-deny egress; resource/parser isolation; synthetic data only.

## Adversarial maturity review

| Attack/failure | Required Wave 1 control | Evidence gate |
|---|---|---|
| Client forges owner intent | authenticated exact endpoint; server-side proposal lookup; secret never returned | forged/missing decision fails, zero provider calls |
| Rejected proposal acts | rejection receipt has no lease; proposal becomes terminal | rejected effect fails, zero provider calls |
| Action/scope/diff/policy/profile tamper | lease HMAC binds all values; gate rechecks exact current context | mutation matrix fails before provider |
| Expired/not-yet-valid lease | injected clock; use-time bounds | both time negatives fail before provider |
| Lease replay | durable single-use reservation before provider access | second use fails, one provider call |
| Concurrent duplicate | in-process replay lock plus durable `EXECUTING` reservation | concurrent pair yields one provider call |
| Crash/ambiguous prior execution | loaded `EXECUTING` stays fail-closed and blocks retry | restart fixture denies retry |
| Wrong provider readback | action-specific semantic comparison of intended material fields | wrong readback creates no success receipt |
| Persisted-store tamper | strict schema/record validation on load; digest verification for terminal receipts | malformed/tampered store refuses startup |
| Owner decision replay | proposal is terminal after first owner choice | second decision denied |
| Live-LLM overclaim | UI/docs preserve deterministic static-policy wording | documentation/static page test |

### Accepted residuals, explicitly outside Wave 1

- Local bearer-token possession stands in for production owner IAM/MFA.
- HMAC keys and state share one local runtime trust domain; compromised host or
  Docker daemon is outside the isolation claim.
- No revoke endpoint, distributed clock, multi-process lock, HA consensus,
  provider transaction, or compensating rollback is claimed.
- Consuming authority before mutation means provider failure requires a new
  owner decision. This intentionally prefers fail-closed safety over retry.
- A process crash after provider acceptance remains `AMBIGUOUS`; blind retry is
  denied and manual/provider reconciliation is required.

These residuals are acceptable for the isolated local deterministic PoC and are
prominently documented; none is represented as production authority.

## CHECK — black/white verification matrix

White tests:

- deterministic escalation returns exact order action, readable diff and bound
  digests;
- owner approval emits a valid short lease and decision receipt;
- approved order mutates once, semantic readback matches, and both stored
  decision/effect receipts read back by digest/key;
- existing deterministic contact auto-grant and installer flow remain green.

Black tests (all assert zero provider calls unless testing replay after one):

- reject; malformed/missing decision; duplicate owner decision;
- tampered action, action digest, scope, diff digest, policy/profile generation,
  lease fields, decision receipt digest or HMAC;
- not-before, expiry, consumed lease, conflicting replay key;
- simultaneous duplicate calls and restart with `EXECUTING` state;
- semantic readback mismatch and tampered persisted store.

Fast development gate: targeted Node tests, TypeScript build/lint, then the full
repository unit/integration test command. Endpoint source/route and dashboard
tests must cover the new endpoints and controls.

Frozen-byte gate: hash relevant tracked bytes, record commit/worktree state, then
run exactly one `SAFE_DEMO_COLD` full install/demo smoke. Do not rerun it unless a
real fixing byte changes; record the changed byte and justification first.

## DO — implementation order and safe parallelism

No implementation writes are parallel. Order:

1. Add proposal/business-diff and durable workbench contracts.
2. Add gate lease issuance, validation/reservation and semantic readback.
3. Wire authenticated owner decision and receipt-readback endpoints.
4. Add dashboard controls and update honest claims.
5. Add/expand fast tests; repair only from evidence.
6. Freeze bytes, hash, run the single full smoke, and archive evidence.

Read-only scouting was safe in parallel because the three topics had no shared
write surface. Gate/runtime/UI implementation is serialized because all paths
share digest semantics and test fixtures.

## ACT — rollback and evidence rules

- Rollback is local: revert the Wave 1 feature commit or delete the isolated
  clone. No remote, release, tag or main state is modified.
- If a compatibility regression cannot be isolated, retain this document and
  tests but defer runtime code; do not weaken a negative gate.
- If the full smoke exposes a bug, first record the evidence, then change the
  minimum fixing byte, update the frozen digest, justify one rerun, and run it
  once. Environmental/transient failures do not authorize an unchanged rerun.
- A successful smoke does not authorize push, PR, release or production use.

## Maturity decision

Wave 1 is implementation-ready because its trust boundary, state transitions,
positive/negative evidence, compatibility boundary, rollback, claim limits and
no-repeat install rule are explicit. Provider-neutral policy code and Paperless
are not implementation-ready in this wave and are intentionally deferred behind
their own measurable gates.
